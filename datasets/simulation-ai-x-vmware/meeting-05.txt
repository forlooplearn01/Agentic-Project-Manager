Sarah Okonkwo: LLM graph spec quality test - removing sample rows?

Jordan Mills: This was interesting. I ran ten different natural language graph requests against the agent, five with sample rows included in the context and five without. Quality difference was minimal for structured requests - like "show CPU utilization over time" - the agent produces an equally good graph spec with or without sample rows because the column names and statistics give it enough to work with. For more ambiguous requests - like "show me what's going wrong in cluster-beta" - the sample rows helped the agent identify which columns had anomalous values. So my recommendation is: include column names and statistics always, include sample rows only for more complex or open-ended requests, and default to omitting them for straightforward structured requests.

Sarah Okonkwo: That's a nuanced approach. Can you implement that adaptively?

Jordan Mills: Yes. I'll classify the user's request as structured or exploratory before building the context. Structured requests are ones that name specific metrics - like CPU, memory, disk. Exploratory requests are more open-ended. For structured requests, no sample rows. For exploratory requests, sample rows included but limited to five rows rather than ten to reduce token usage.
