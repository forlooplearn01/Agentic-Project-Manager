1. EXECUTIVE SUMMARY

NovaTech Solutions Inc. (hereinafter referred to as "Client") has engaged QuantumEdge AI Consulting LLC (hereinafter referred to as "Provider") to design, develop, and deploy an AI-powered infrastructure analytics and reporting platform. The platform will integrate with VMware Aria Operations (formerly vRealize Operations) via its REST API and support CSV-based data ingestion as a fallback data source. The system will enable NovaTech's infrastructure team to generate dynamic visualizations and executive-level PDF reports driven by natural language user inputs and AI agent decision-making.

This Statement of Work outlines the scope, deliverables, timeline, team responsibilities, assumptions, and terms governing the engagement between NovaTech Solutions Inc. and QuantumEdge AI Consulting LLC for the AI-X-VMware project.

2. BACKGROUND AND BUSINESS NEED

NovaTech Solutions Inc. operates a large-scale VMware virtualization environment spanning multiple clusters, resource pools, and hundreds of virtual machines. The infrastructure team currently relies on manual data exports and ad hoc spreadsheet analysis to generate performance reports for executive stakeholders. This process is time-consuming, error-prone, and does not scale with the growing complexity of the environment.

The Client requires an intelligent, self-service analytics platform that:

a. Allows users to select between live VMware Aria Operations data (via Stat Key API endpoint) and locally stored CSV datasets as the data source.
b. Enables natural language interaction to specify the type of graphs and metrics to visualize.
c. Leverages an AI agent to intelligently select relevant datasets and generate multiple graphs automatically.
d. Supports cross-cluster and cross-resource data aggregation for complex comparative analysis.
e. Produces polished executive summary reports in PDF format, combining AI-generated narrative summaries with the generated graphs.
f. Stores all generated reports and graphs in a designated output directory for future access and audit.

This engagement will deliver a fully functional, production-ready platform within an eight-week timeline, including design, development, testing, and production deployment.

3. SCOPE OF WORK

3.1 In-Scope

The following activities and deliverables are within the scope of this engagement:

3.1.1 Data Source Integration Module
- Design and implement a data source selection interface allowing users to choose between CSV file ingestion and live VMware Aria Operations API integration.
- Implement CSV ingestion: list available CSV files from a configured folder, allow user upload of new CSV files to the folder, and parse and validate CSV structure upon selection.
- Implement VMware Aria Operations API integration: authenticate using username and password to obtain a VMwareOpsToken, use the token to query the Stat Key API endpoint, retrieve all available raw metrics datasets for the specified cluster or resource, and handle token expiry and re-authentication gracefully.
- Implement multi-cluster data aggregation: support querying multiple clusters or resources in sequence and merging the resulting datasets for cross-cluster analysis.
- Implement error handling for API connectivity failures, authentication failures, malformed CSV files, and empty datasets.

3.1.2 AI Agent and Graph Generation Module
- Design and integrate an AI agent that accepts natural language user input describing the desired graph type and metrics.
- Implement dataset selection logic: the AI agent analyzes available datasets and selects the most relevant columns and rows to satisfy the user's request.
- Implement graph generation: support at least five graph types including line charts, bar charts, scatter plots, heatmaps, and pie charts.
- Implement multi-graph generation: the AI agent generates multiple graphs in a single session based on user input.
- Implement graph storage: save all generated graphs as image files (PNG format) in the designated output directory with timestamped filenames.
- Support complex graph scenarios: combine and compare data from multiple clusters or resources in a single graph.

3.1.3 Report Generation Module
- Implement a report title input prompt allowing the user to specify the title of the executive summary report.
- Design and implement an AI-generated executive summary narrative that contextualizes the graphs and key findings.
- Compile all generated graphs and the executive summary into a structured PDF report.
- Apply professional formatting to the PDF including a cover page, table of contents, section headers, graph captions, and a footer with generation timestamp and report title.
- Store the generated PDF report in the designated output directory with a timestamped filename.

3.1.4 Output Management
- Design and implement an output directory structure for storing graphs and reports.
- Implement a report index file (JSON format) that catalogs all generated reports and graphs with metadata including generation timestamp, data source used, cluster or resource queried, and report title.
- Ensure all output files are accessible and retrievable at any time without re-running the pipeline.

3.1.5 Testing and Quality Assurance
- Conduct unit testing for all individual modules: data source integration, AI agent, graph generation, and report generation.
- Conduct integration testing for the end-to-end pipeline from data source selection to PDF report storage.
- Conduct user acceptance testing (UAT) with NovaTech's infrastructure team using real VMware Aria Operations data and pre-prepared CSV datasets.
- Conduct performance testing for multi-cluster data aggregation scenarios.
- Document all test cases, test results, and defect resolutions.

3.1.6 Production Deployment
- Deploy the platform to NovaTech's designated production environment.
- Configure environment variables, API credentials, and output directory paths for the production environment.
- Conduct a smoke test post-deployment to verify all modules function correctly in production.
- Provide a deployment runbook documenting all deployment steps, configuration requirements, and rollback procedures.

3.1.7 Knowledge Transfer and Documentation
- Conduct a knowledge transfer session with NovaTech's infrastructure team covering platform architecture, usage, and maintenance.
- Deliver a user guide documenting the data source selection workflow, graph generation workflow, and report generation workflow.
- Deliver a technical reference document covering the API integration design, AI agent architecture, and output directory structure.

3.2 Out of Scope

The following are explicitly excluded from this engagement:

- Integration with any data source other than VMware Aria Operations API and CSV files.
- Development of a web-based or mobile user interface (the platform will operate as a command-line or script-based application in this phase).
- Real-time streaming or continuous monitoring of VMware metrics.
- Integration with ticketing systems, ITSM platforms, or alerting systems.
- Custom VMware Aria Operations configuration or administration.
- Procurement or licensing of VMware Aria Operations or any third-party tools.
- Ongoing post-deployment support beyond the scope of this engagement (covered under a separate support agreement if required).

9. ACCEPTANCE CRITERIA

9.1 Data Source Integration Module is accepted when:
- The user can successfully select between CSV and live API data sources.
- CSV file listing, upload, and ingestion function correctly with valid and invalid inputs.
- VMware Aria Operations authentication succeeds and returns a valid token.
- Stat Key API endpoint returns raw metrics data for a specified cluster.
- Multi-cluster data aggregation correctly merges datasets from at least two clusters.

9.2 AI Agent and Graph Generation Module is accepted when:
- The AI agent correctly interprets at least five distinct natural language graph requests.
- At least five graph types are generated correctly with appropriate labels and titles.
- Multi-graph generation produces at least three graphs in a single session.
- All graphs are saved as PNG files in the output directory with correct filenames.

9.3 Report Generation Module is accepted when:
- The user can input a custom report title.
- The generated PDF contains a cover page, table of contents, executive summary narrative, all generated graphs with captions, and a timestamped footer.
- The PDF is saved in the output directory with a timestamped filename.
- The report index JSON file is updated with the correct metadata for the new report.

9.4 Production Deployment is accepted when:
- All modules function correctly in the production environment.
- Smoke test passes for both CSV and live API data source workflows.
- Deployment runbook is reviewed and approved by Priya Nair.
