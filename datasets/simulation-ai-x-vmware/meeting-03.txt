Sarah Okonkwo: Exactly. Jordan, let's talk about the AI agent design. This is the big one starting next week. Walk us through your current thinking.

Jordan Mills: So I've been designing the AI agent architecture in parallel with the API integration work. Here's the current design. The agent is a LangChain ReAct agent backed by GPT-4o. It receives a dataset summary - which is the structured description from the data loader with column names, types, statistics, and sample rows - and a natural language user input describing what they want to visualize. The agent's job is to reason about the dataset summary, identify the most relevant columns and data, and produce a structured graph specification. The graph spec is then passed to the rendering layer which uses Matplotlib and Seaborn to actually generate the image files.

Marcus Webb: What does the graph specification look like? Is it a JSON structure?

Jordan Mills: Yes. It's a JSON object with fields like graph_type, x_axis, y_axis, color_by, title, and filters. For example, if the user says "show me CPU utilization over time for all VMs in cluster-alpha," the agent would produce something like: graph type is line chart, x_axis is timestamp, y_axis is cpu|usage_average, color_by is resource_name, title is "CPU Utilization - Cluster Alpha," and filters would be empty since they want all VMs.

Marcus Webb: What if the user asks for something that doesn't map cleanly to the available data? Like they ask for network throughput but that stat key isn't in the dataset?

Jordan Mills: Good question. I'm building a fallback mechanism - if the agent can't find the exact stat key the user asked for, it looks for semantically similar ones using the stat key normalization layer and presents the user with alternatives. Like, "I couldn't find network throughput but I found net|usage which represents network utilization. Would you like to use that?" It's a graceful degradation rather than an error.

Marcus Webb: That's a great UX approach. Should I document that as a requirement?

Jordan Mills: Yes. Add it as "semantic stat key fallback with user confirmation."

Jordan Mills: My current thinking is to sort columns by a relevance score before truncating.
